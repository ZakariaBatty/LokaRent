                                    WORKSPACE PAGES DETAIL
═══════════════════════════════════════════════════════════════════════════════════════════════════

┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│ /workspace/agencies                                                                              │
│ ────────────────────                                                                            │
│ Purpose: Central agency directory for workspace admin                                           │
│ Pattern: Full-width table → Slide-over detail panel (80%)                                      │
│ Filters: Status (Actif/Suspendu), Plan (Starter/Pro/Enterprise)                               │
│ CRUD: View only (display revenue, status, KPIs)                                                │
│ Detail Tabs: Agence | Finances | Opérations | Membres | Abonnement | Activité                 │
└──────────────────────────────────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│ /workspace/members ✓ (PRIMARY USER MANAGEMENT)                                                  │
│ ──────────────────                                                                              │
│ Purpose: Cross-agency user management (single source of truth)                                 │
│ Pattern: Split-layout (20% compact list | 80% sticky panel)                                   │
│ Filters: Search, Role, Status, Agency                                                         │
│ CRUD: Add (form sheet), Edit (inline role change), Delete (confirm dialog), Assign agency    │
│ Detail Tabs: Informations | Accès agences | Rôles | Équipes | Permissions | Activité          │
│ Features: Multi-agency assignment, per-agency role visibility, recent activity                │
└──────────────────────────────────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│ /workspace/permissions ✓ (PRIMARY PERMISSIONS MANAGEMENT)                                       │
│ ──────────────────────                                                                          │
│ Purpose: Role-Based Access Control (RBAC) with user + agency overrides                        │
│ Pattern: Three-view switcher (Par rôle | Par utilisateur | Par agence)                         │
│ View 1 - Par rôle: Role list → Permission matrix (9 modules × 5 actions)                       │
│ View 2 - Par utilisateur: User list (avatar+email+role+agencies) → Matrix + agency switcher   │
│ View 3 - Par agence: Agency list → Members of agency → Per-member matrix                      │
│ Features: Inline edit, dirty-state tracking, Enregistrer button, per-module granularity        │
│ Data: rolePermissions (baseline) + mockUserPermissionOverrides (exceptions)                    │
└──────────────────────────────────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│ /workspace/teams                                                                                │
│ ────────────────                                                                               │
│ Purpose: Read-only directory of all workspace teams                                            │
│ Pattern: Full-width table → Slide-over detail panel (80%)                                      │
│ Filters: Search, Agency (optional)                                                             │
│ CRUD: View only                                                                                 │
│ Note: Team editing happens in /settings/teams (agency-scoped) — add breadcrumb link            │
└──────────────────────────────────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│ /workspace/invitations                                                                          │
│ ──────────────────────                                                                         │
│ Purpose: Manage pending workspace member invitations                                           │
│ Pattern: Tab switcher (All | Pending | Accepted | Expired) → Table of invites                │

│ Features: Email sending, 7-day expiry, status tracking                                         │
└──────────────────────────────────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│ /workspace/billing                                                                              │

                                    DATA FLOW ARCHITECTURE
═══════════════════════════════════════════════════════════════════════════════════════════════════

USER DATA LAYERS:
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│ Level 1: Global Users (mockGlobalUsers)                                                        │
│ ────────────────────────────────────                                                           │
│ • All workspace users in one place                                                             │
│ • Contains: id, firstName, lastName, email, phone, createdAt, lastLoginAt               │
│ • Query: No agency filtering                                                                   │
│ • Location: /workspace/members (shows all users)                                               │
│ • Data Source: mock-workspaces.ts                                                             │
└──────────────────────────────────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│ Level 2: Agency Memberships (mockMemberships)                                                  │
│ ──────────────────────────────────────────────                                                │
│ • Cross-join: User × Agency (one user → multiple agencies)                                    │
│ • Contains: id, userId, agencyId, role, status, joinedAt, invitedBy, invitedAt             │
│ • Query: Filter by userId → get all agencies user belongs to                                  │
│ • Query: Filter by agencyId → get all members of that agency                                 │
│ • Statuses: active | pending | suspended | expired                                            │
│ • Data Source: mock-workspaces.ts                                                             │
└──────────────────────────────────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│ Level 3: Team Memberships (mockTeams + team_members join)                                       │
│ ───────────────────────────────────────────────────────────                                    │
│ • Teams are agency-scoped                                                                      │
│ • Each team contains: id, agencyId, name, description, memberIds[]                            │
│ • Query: Filter by agencyId → get all teams in that agency                                    │
│ • Query: Filter by team.memberIds → get all members of team                                  │
│ • Data Source: mock-workspaces.ts                                                             │
└──────────────────────────────────────────────────────────────────────────────────────────────────┘


PERMISSION LAYERS:
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│ Level 1: Role Baseline (rolePermissions)                                                       │
│ ──────────────────────────                                                                    │
│ • 6 roles: OWNER, ADMIN, MANAGER, TEAM_LEAD, EMPLOYEE, CLIENT                              │
│ • Each role has matrix: 9 modules × up to 5 actions                                          │
│ • Module list: dashboard, cars, reservations, clients, contracts, finances, reports, ...     │
│ • Actions: read, create, update, delete, export                                              │
│ • Example: rolePermissions['MANAGER'].cars = ['read', 'update']                             │
│ • Data Source: mock-workspaces.ts (rolePermissions table)                                    │
└──────────────────────────────────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│ Level 2: User Overrides (mockUserPermissionOverrides)                                          │
│ ────────────────────────────────────────────────────────                                      │
│ • Exceptions to role baseline                                                                  │
│ • Each override: userId, agencyId, module, actions[]                                         │
│ • Example: "Youssef can read finances in Marrakech (not normally allowed for TEAM_LEAD)"    │
│ • Tracks: grantedBy, grantedAt, note                                                        │
│ • Computed: Effective permissions = baseline ∪ overrides                                     │
│ • Data Source: mock-workspaces.ts (mockUserPermissionOverrides array)                        │
└──────────────────────────────────────────────────────────────────────────────────────────────────┘


AUDIT TRAIL:
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│ Audit Logs (mockAuditLogs)                                                                     │
│ ─────────────────────────────                                                                 │
│ • Every action logged: create, read, update, delete, export, sign, invite, revoke           │
│ • Fields: id, agencyId, userId, action, resource, resourceId, details, createdAt            │
│ • Queryable: by userId, by agency, by action, by resource                                    │
│ • Example: "Ahmed created reservation RES-2026-0098 for Peugeot 208"                       │
│ • Data Source: mock-workspaces.ts (mockAuditLogs array)                                      │
└──────────────────────────────────────────────────────────────────────────────────────────────────┘
